# 평가

문서 유형과 검증 축별 정답셋, 회귀 사례, 평가 설정과 결과를 분리한다. 정답 출처·규모·통과 기준이 확정되기 전에는 임의 데이터를 작성하지 않는다.

## 데이터셋 생성 등급

- A: 결정론적 변형이 가능한 규칙
- B: 여러 유효한 답이 있어 생성·사람 검토가 필요한 규칙
- C: 외부 사실이 필요해 실제 사례가 필요한 규칙

등급은 위반 사례를 만드는 방법을 구분하며 데이터셋 `split`과는 다르다.

## v1.1 인스턴스 형식

정식 형식은 노션 데이터셋 문서와 정답 검수 절차를 기준으로 `datasets/`에서 관리한다. 스키마와 인스턴스는 실제 평가 데이터와 분리한다.

`split`은 `cbr`, `dev`, `test`만 사용한다. 같은 `base_doc_id`에서 파생된 원본과 합성본을 서로 다른 split에 놓지 않아 누수를 막는다. `labels`는 발견한 위반, `checked_rules`는 실제 확인한 규칙이므로 어떤 규칙이 두 목록에도 없으면 정상이 아니라 미확인으로 처리한다.

Writing Case와 Correction Case, 최종 평가셋은 분리한다. 실제 보고서나 사용자가 채택한 수정안은 전문가 또는 승인 절차 없이 정답으로 승격하지 않는다.

제안된 데이터셋 수량은 제안값이다. 승인된 gold set과 H0 설정이 생기기 전에는 품질 게이트로 사용하지 않는다.
