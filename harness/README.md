# 하네스

최신 구조 문서는 [`docs/harness/harness-v1.2.md`](../docs/harness/harness-v1.2.md)이다.

처음 사용하는 팀원은 [전체 개발·하네스 가이드](../docs/guide/development-guide.md)를 먼저 읽는다.

하네스는 두 역할로 나뉜다.

- 개발 과정 하네스는 Issue·계약·ID·정적 검사·CI·PR 증거를 연결한다.
- 제품 AI 하네스는 입력·파싱·규칙·검색·판정·근거·출력·평가를 검증한다.

`policy.json`은 저장소의 필수 경로와 활성 검사를 정의한다. 검사기는 구조, JSON 문법, Schema 헤더, ID 형식·중복, Markdown 로컬 링크, 비밀정보 패턴, GitHub 관리 기획 문서 표식과 백엔드 검증 연결 상태를 검사하고 JSON 리포트를 생성한다.

제품 품질 평가, 계약 인스턴스 검증, 영역별 빌드·린트·타입 검사는 관련 기능과 기술 스택이 추가될 때 실패 사례와 수용 기준을 근거로 연결한다. RMA는 라우팅, 규칙·RAG·LLM은 검증, CBR은 확정 이슈의 수정 보조를 담당한다.
