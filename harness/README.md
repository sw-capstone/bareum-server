# 하네스

최신 구조 문서는 [`docs/harness/harness-v1.4.md`](../docs/harness/harness-v1.4.md)이다.

처음 사용하는 팀원은 [전체 개발·하네스 가이드](../docs/guide/development-guide.md)를 먼저 읽는다.

이 하네스는 `bareum-server` 내부만 검사한다. 웹은 자체 CI에서 `npm run check`를 실행하고, `bareum-ai`의 하네스와 CI는 AI 저장소 내부를 검사한다. 제품 AI 평가 검사는 관련 기준과 자산이 준비되면 확장한다.

각 영역 담당자가 검사 코드와 사례를 작성하고 하네스 담당자를 필수 리뷰어로 지정한다. 이슈·PR 본문은 사람이 검토하며 현재 검사기가 자동 파싱하지 않는다.

`policy.json`은 저장소의 필수 경로와 활성 검사를 정의한다. 현재 검사기는 구조, JSON 문법, Markdown 로컬 링크와 서버 구현 요약 문서의 필수 표식을 검사하고 JSON 리포트를 생성한다. Schema 헤더·예시와 ID 레지스트리 검사는 코드가 있지만 대상이 없어 `not_applicable`이다. 문서 표식 통과는 기능 동작 검증을 뜻하지 않는다.

Schema 예시를 정책에 등록해 로컬에서 검증할 때는 `python -m pip install -r harness/requirements.txt`로 의존성을 설치한다. 의존성이 없는 환경에서는 일부 규칙만 검사해 통과시키지 않고 Schema 검사를 실패 처리한다.

제품 품질 평가, 계약 인스턴스 검증, 영역별 빌드·린트·타입 검사는 관련 기능과 기술 스택이 추가될 때 실패 사례와 수용 기준을 근거로 연결한다. RMA·RAG·LLM·CBR의 구체 책임과 검사도 해당 기능이 확정되고 구현될 때 추가한다.

## 정책 검증

정책 파일은 `version`, `required_paths`, `checks`를 갖는 JSON 객체다. 버전은 비어 있지 않은 문자열, 필수 경로는 문자열 배열, 검사 설정은 지원하는 검사 이름과 Boolean 값으로 작성한다. 검사 설정에서 생략한 이름은 기존 방식대로 활성화되므로, 검사를 끄려면 해당 이름에 `false`를 명시한다.

알 수 없는 항목·검사 이름, 중복 JSON 키, 잘못된 자료형, 빈 경로와 저장소 밖을 가리키는 경로는 `HAR-POLICY-001`로 실패한다. 경로는 저장소 내부의 상대 경로를 사용하며, 심볼릭 링크가 저장소 밖으로 연결되는 경우도 허용하지 않는다. 등록한 파일의 존재 여부는 각 검사가 확인한다. 비활성 검사에 남아 있는 설정도 형식과 경로를 검증한다.

`schema_examples`의 Schema·예시 경로와 `product_spec`의 문서 경로·필수 표식도 검증한다. 자동 수정 설정의 자료형을 확인하더라도 자동 수정 기능을 실행하지는 않는다.

UTF-8로 표현할 수 없는 정책 문자열도 정책 오류로 처리하고 실패 리포트를 남긴다. 정상적인 한글과 이모지 문자열은 허용한다.
