# 인프라 아키텍처 반영 상태

현재 공유 문서에는 인프라 아키텍처 본문이 아직 작성되지 않았다. 따라서 이 파일은 기술 스택을 확정하는 설계서가 아니라, 현재 레포에서 확인 가능한 경계와 미결정을 기록한다.

## 현재 반영 범위

- `bareum-server/.github/workflows/harness.yml`: 서버 레포의 문서·계약·하네스 검사와 자체 테스트
- `bareum-web/.github/workflows/ci.yml`: 프론트 레포의 의존성 설치와 `npm run check`
- `infra/README.md`: 로컬 실행·컨테이너·CI·배포·관측 설정의 자리
- 제품 배포 환경, 데이터베이스, 큐, 스토리지, 비밀정보, 관측 도구와 네트워크 구성은 아직 확정하지 않는다.

## 아키텍처 문서 작성 전 원칙

인프라 아키텍처 문서가 작성되면 다음 항목을 확인하고 이 파일과 하네스 정책을 함께 갱신한다.

1. API와 AI Worker의 실행 단위 및 이미지 경계
2. 로컬 Compose와 배포 환경의 차이
3. 데이터베이스·파일 저장소·큐의 소유권과 보존·삭제 정책
4. 비밀정보·권한·네트워크 경계
5. CI/CD, 롤백, 로그·메트릭·트레이스의 수집 범위
6. 비용·처리시간·동시성·복구 목표

본문이 없는 상태에서 특정 클라우드, DB, 큐, 배포 방식을 하네스 통과 조건으로 만들지 않는다. 인프라 구현이 시작되면 재현 가능한 로컬 명령과 CI 검사를 먼저 추가한다.
