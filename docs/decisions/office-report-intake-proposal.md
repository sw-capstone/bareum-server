# HWPX와 DOCX 보고서 공통 본문 및 접수 연동

- 상태: 합의 반영
- 관련: #60, #51, #53, PR #67

## 공통 본문

DOCX와 HWPX를 공통 본문 1.1.0으로 저장한다. PDF와 직접 입력의 1.0.0 저장 및 읽기는 유지한다. 본문 구성, 문장 분리와 검증은 기존 BodyInput, BodyAssembler, ReportBody를 사용한다.

- 문서 내부 위치는 SourceRef의 officeLocation에 ZIP part와 XML 요소 경로로 기록한다. 문자 범위는 해당 요소의 추출 텍스트에서 Unicode 코드 포인트 기준 반열린 구간이다. 표 구조 참조는 문자 범위를 생략하고 셀은 원래 행과 열을 함께 기록한다.
- 의미가 확실하지 않은 텍스트는 para를 사용한다. 화면 렌더링의 실제 줄 수는 알 수 없으므로 lineCount를 생략하고 LINE_COUNT_UNAVAILABLE을 기록한다.
- 본문, 표, 병합 셀, 표 캡션의 텍스트와 주변 설명을 보존한다. 표 안이나 바로 옆의 명시적인 단위 표기는 unitNoteRefs로 연결한다.
- 중첩 표, 글상자, 각주 등 추출 범위에서 제외된 요소가 발견되면 원문 위치와 이유를 경고로 남기고 PARTIAL로 저장한다. 추출할 본문이 없으면 실패로 처리한다.

## 접수 API

기존 `POST /api/v1/reports`의 인증, 멱등 키, 접수 및 시도 상태, S3 원본 보관과 삭제를 재사용한다. 파일의 형식과 MIME을 원본 저장까지 전달한다. PDF는 기존 AI 파서를 호출하고 DOCX와 HWPX는 동일한 업로드 원본을 Spring에서 로컬 파싱한다. 두 경로가 검증된 공통 본문과 추출 품질을 반환하면 기존 완료 명령이 저장한다.

20,000,000바이트 상한은 모든 형식에 적용한다. 60쪽 제한은 PDF에만 적용한다. DOCX·HWPX는 XML 보호 상한과 공통 접수 처리 기한·동시 처리 제한을 사용한다. 형식 불일치와 추출할 본문 없음은 기존 오류를 재사용하고 읽을 수 없는 DOCX·HWPX는 REPORT-0058로 처리한다.

## 소비자 연동

AI 소비자는 1.1.0을 읽고 줄 수가 필요한 검사와 부분 추출의 영향을 받는 검사만 미수행으로 표시한다. 서버는 누락 위치와 경고를 제공한다. 업로드 화면에는 PDF에만 60쪽 제한이 적용된다는 안내를 표시한다. 소비자 구현 및 통합 검증은 각 저장소에서 수행한다.
