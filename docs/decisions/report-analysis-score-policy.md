| 항목 | 내용 |
| --- | --- |
| 상태 | MVP 우선 적용 |

| 소유 역할 | 백엔드 |

## 쟁점과 결정

종합 점수를 MVP에 포함하는 안과, 산정 기준이 확정될 때까지 제공을 보류하는 안을 검토했다. 분석과 결과 리포트 흐름을 이어서 구현할 수 있도록 MVP에는 종합 점수를 우선 포함한다. 종합 점수를 저장한 뒤 결과 리포트를 생성한다.

## 현재 저장 제약

- `report_analysis.total_score`는 `NUMERIC(5, 2)`이며, 점수를 저장하기 전까지는 비어 있을 수 있다.
- `ReportAnalysis.recordScore()`는 `PROCESSING` 상태에서만 호출할 수 있다. 입력값은 `0` 이상 `999.99` 이하이며, 소수부는 끝의 0을 제외하고 최대 두 자리까지 허용한다. 이 범위는 현재 저장 규격이다. 서비스 만점은 미정이다.
- 같은 점수를 다시 받으면 기존 값을 유지한다. 이미 저장한 점수를 다른 값으로 덮어쓰는 요청은 거절한다.
- 리포트 생성만 최종 실패하면 점수를 유지한다. 분석을 취소하면 실행 기록을 남기고 점수를 비운다.

## 영향과 재검토 조건

점수 저장 후에도 분석은 `PROCESSING`으로 유지하고, 결과 리포트 저장이 끝나면 `SUCCEEDED`로 전환한다. 이 상태 전환은 [보고서 분석 흐름](../product/report-analysis-flow.md)에서 확인할 수 있다.

AI 산정 기준이 구체화되면 만점, 계산식, 소수점 처리 방식을 확정하고 입력 검증과 저장 규격을 재검토한다. MVP에서 점수 제공 여부가 바뀌면 리포트 생성 전 점수 필수 조건도 함께 재검토한다.
