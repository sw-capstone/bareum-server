# Auth·Term 적용안 및 팀 검토 항목

기존 미정 항목을 개발용 임시 기준으로 구체화했다. 팀 최종 승인·실제 배포와 구분하며 최신 기준은 [공유 협의 문서](https://app.notion.com/p/3f911880adea809591b6f654f8e45597)를 따른다. 인증 실패 복구 등 후속 정책 구현은 #54에서 추적하며 이 배포 정비 변경에 모두 포함된 것으로 취급하지 않는다.

## 1. 약관
- **구현 기준:** 네 boolean 동의, 필수 동의 검증, DB 약관에 동의 이력을 연결한다. 버전 비교·유효성 검증과 관련 503은 이번 개발에서 제외한다.
- **개발 기준:** 최종 원문 확정은 뒤로 미루고 네 항목에 임시 표시용 문구를 사용해 동의·미동의 흐름을 개발한다. 프론트는 임시 원문, 서버는 동의 저장에 필요한 네 약관의 개발용 DB 메타데이터를 준비한다. 공식 약관 확정으로 취급하지 않으며 실제 사용자 적용 전 표시 원문과 DB 기록 기준을 확인한다.
- **팀 검토 질문:** 최종 원문·버전이 준비되었는가? 프론트 표시와 서버 데이터의 반영 담당자는 누구인가?

## 2. 개발 도메인·쿠키
- **주소 확인:** 현재 프론트 후보는 `https://bareum-web-git-develop-numkites-projects.vercel.app`, API는 `https://api.bareum.site`다. Vercel 주소를 계속 사용할지 bareum.site의 프론트 도메인으로 전환할지 프론트·인프라와 확인한 뒤 허용 Origin을 확정한다. HttpOnly·Secure·SameSite=None 쿠키 기준은 유지한다.
- **외부 검증:** 배포 설정 적용과 실제 브라우저의 쿠키 전달은 별도로 확인한다.
- **팀 검토 질문:** 이 주소로 연동할 수 있는가? 타사 쿠키 차단 시 같은 사이트 도메인으로 전환할 것인가?

## 3. 이메일 인증·재발송·복구
| 항목 | 개발 적용안 |
| --- | --- |
| 가입 번호·완료 증명 | 기존 300초·600초 유지 |
| 재설정 번호·완료 증명 | 300초·600초 |
| 발송 간격·횟수 | 60초·최근 1시간 5회·24시간 20회 |
| 인증 실패 제한·복구 | 5회 실패 후 15분 대기, 새 번호 접수 시 새 시도 시작 |
| 완료 증명 분실 | 기존 재발송 API로 재인증, 새 접수와 함께 이전 미사용 증명 무효화 |

- **기존 명세 유지:** 재발송 자체는 실패 횟수를 초기화하지 않는다. 제한 시간이 지난 후 새 번호를 요청해야 한다.
- **구현 영향:** 기존 확인·재발송 계약을 사용하며 완료 증명 원문 재조회는 제공하지 않는다. 계정·로그인은 정지하지 않는다.
- **팀 검토 질문:** 실패 5회·15분과 재설정 증명 10분으로 시작해도 되는가? 재인증 시 기존 증명 무효화 안내가 적절한가?

## 4. Google 지원 계정
- **임시 적용안:** Gmail·검증된 Workspace 신규 가입만 허용한다. 제3자 이메일은 AUTH-0028/403으로 안내한다.
- **생성 순서·담당:** 프론트 연동 주소 확정 후 백엔드 담당 이서현이 바름용 Google 프로젝트·웹 Client ID를 생성하고 프론트에 공유한다. 인프라 담당자와 서버의 `GOOGLE_CLIENT_IDS` 적용을 연결한다. 주소 확인 전에는 생성·등록을 진행하지 않는다.
- **개발·검증 경계:** Client ID 준비 전에도 서버 로직·모의 검증과 프론트 코드 준비는 가능하다. 실제 Google 인증·브라우저 통합 검증은 Client ID·승인 Origin·서버 설정을 맞춘 뒤 진행한다.
- **팀 검토 질문:** 이번 범위의 지원 제한을 유지할 것인가? 제3자 이메일 추가 인증이 필요하면 별도 화면·계약과 함께 확대할 것인가?

## 5. 메일 발송 화면 연동 기준
- **프론트 전달 기준:** 202 접수의 requestId로 1초 간격 조회. PENDING에서는 타이머를 시작하지 않고 별도 지연 안내·1분 초과 실패 처리를 추가하지 않는다.
- **발송 완료:** SENT와 expiresIn > 0을 확인하면 조회를 멈추고 해당 남은 초로 인증 타이머를 시작한다. SENT의 0초는 만료로 처리한다.
- **최종 실패:** FAILED 확인 시 조회를 멈추고 “메일을 보내지 못했습니다. 다시 시도해주세요.”를 표시한다. CANCELLED는 무효화 상태로 구분하고 조회를 중단한다.
- **조회 수명:** 일시적인 상태 조회 통신 오류는 발송 실패로 간주하지 않는다. 조회 요청은 중첩하지 않으며 화면 이탈 시 중단한다. 재발송 접수 후에는 새 requestId만 반영하고 이전 응답은 무시한다.
- **담당·현재 상태:** 상태·남은 시간 반환은 서버에 구현되어 있다. 1초 조회·문구·타이머는 프론트 연결 대상이며 전달·구현·브라우저 검증 완료로 취급하지 않는다. 최초 접수 응답 유실 등 별도 복구 계약은 이 기준으로 새로 확정하지 않는다.
