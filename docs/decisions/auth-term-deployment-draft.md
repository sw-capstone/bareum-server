# Auth·Term 배포 설정 구현 선택과 협의 사항

- 관련 작업: [#22](https://github.com/sw-capstone/bareum-server/issues/22), [#46](https://github.com/sw-capstone/bareum-server/pull/46)
- 기준: 최신 기술 정책, 기존 Parameter Store·EC2 배포 경로와 Auth·Term 구현
- 상태: 배포 준비 구현 초안 / 아래 선택은 임시로 설정한 팀 미확정 기준

## 쟁점·선택지·영향·재검토 조건

| 쟁점 | 선택지 | 구현 선택·영향 | 재검토 조건 |
| --- | --- | --- | --- |
| 인증 설정 적용 시점 | 기존 배포에서 항상 조회 / 명시적으로 활성화 | `.env.deploy`의 `AUTH_ENV_ENABLED`로 활성화한다. 기본값·누락은 false이며 기존 DB 조회만 유지한다. 인증 코드 배포 전 활성화와 필수 키 준비가 필요하다. | 운영 적용 순서와 인프라 담당자 승인 |
| 설정의 소유 | 템플릿·수동 환경 파일 / Parameter Store | DB와 Auth·Term 값은 기존 `/bareum/dev/server/`에서 허용한 이름만 조회한다. 수동으로 `.env.server`에 추가한 값은 다음 생성 때 유지하지 않는다. | 팀의 공통 설정 관리 방식 변경 |
| 필수 범위 | 기능별 부분 설정 / 이메일 가입·로그인의 핵심 설정을 함께 준비 | JWT 서명 키·HMAC·Outbox·인증 SMTP·발송 제한·Origin·네 약관 버전은 필수다. Google과 재설정 기간은 선택이며 미설정 기능은 기존 차단 동작을 유지한다. | 단계별 출시로 핵심 기능도 별도 활성화해야 할 때 |
| SMTP 보호 | 제공자별 임의 연결 / 인증 SMTP와 암호화 연결 검증 | SMTP 인증을 요구하고 implicit TLS 또는 필수 STARTTLS 중 하나를 허용한다. 서버 이름 검증과 기존 타임아웃을 유지한다. 제공자·계정은 선택하지 않았다. | OAuth 기반 SMTP 등 다른 인증 방식 확정 |
| 조회 원자성 | 현재 이름별 배치 조회 / 설정 버전 묶음·스냅샷 | API 제한에 따라 최대 10개씩 조회하며 모두 검증한 뒤 환경 파일을 교체한다. 여러 배치의 동시 변경까지 원자적으로 보장하지 않는다. | 키 교체·빈번한 설정 변경을 운영할 때 |
| 약관 초기 데이터 | 임시 원문·버전 seed / 승인 후 반영 | 환경변수로 승인 버전만 연결한다. 원문·DB 행을 임의 생성하지 않으며 DB 불일치 시 기존 TERM-0004 차단을 유지한다. | 원문·버전·필수 항목 승인 |

## 남은 팀 결정

- 운영 메일 제공자·발신 계정과 인증 방식
- 발송 간격·시간당/일당 제한, 인증 실패 제한·복구 정책
- 약관 원문·승인 버전·DB 초기 데이터와 실제 배포 Origin
- Google Client ID·승인 Origin·지원 계정 기준
- 비밀번호 찾기의 배포 범위와 재설정 기간
- EC2의 Parameter Store·KMS 권한, 암호화 키 교체 절차와 환경 백업 보관 기준

위 항목을 테스트 값이나 구현 선택으로 확정하지 않는다. 기존 SMTP 실제 수신 검증과 운영 환경 적용 결과는 구분한다. 이번 변경의 API 주소·요청·응답·오류 형식은 유지한다.

구현된 주입 경로와 설정별 확인 기준은 [배포 설정 준비](../guide/auth-term-deployment.md)를 따른다.

## 검증 결과

- `./gradlew check bootJar --no-daemon`: Auth·Term 통합 구현 기준 전체 683개 통과, 실패·오류·건너뜀 0개 및 JAR 빌드 성공.
- 추가 설정 바인딩 10개 사례로 실제 YAML·환경변수에서 승인 약관 버전, SMTP 인증·TLS·서버 이름 검증·타임아웃, 발송 제한과 로그인·Google 설정 연결을 확인했다.
- 환경 생성 회귀 검사 16개 통과, POSIX 심볼릭 링크 권한 검사 1개는 별도 CI 환경에서 확인한다. 모의 SSM 응답을 사용한다. 필수 값·SecureString·암호화 키·TLS·Origin·약관 버전 검증, 기존 환경 보존과 비밀값 비노출을 검사하며 실제 AWS 권한·SMTP 수신 검증을 대신하지 않는다.
- Bash 문법·ShellCheck와 하네스 정적 검사 통과. 실제 EC2·Parameter Store 적용과 브라우저·Google 계정 연동은 별도 검증 대상이다.
