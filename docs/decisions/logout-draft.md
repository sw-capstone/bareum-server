# 로그아웃 적용 기준

- 갱신일: 2026-10-28
- 상태: 구현안·팀 검토 필요
- 대상: AUTH-003, [Issue #25](https://github.com/sw-capstone/bareum-server/issues/25), BRM-28 / #39
- 기준: [로그아웃 명세](https://app.notion.com/p/f5a11880adea82a5ac6f01cd592a59ae), 기술·정책 명세와 화면 기획의 이메일·Google 공통 로그인 종료를 따른다. 아래 요청·응답과 상세 폐기 정책은 리뷰 대상 구현안이다.

## API와 프론트 처리

`POST /api/v1/auth/logout`

- 본문·Access Token 없이 Refresh 쿠키와 CSRF 헤더로 호출한다. 먼저 `GET /api/v1/auth/csrf`에서 받은 마스킹된 token을 `X-CSRF-TOKEN` 헤더로 전달하고 두 요청에 `credentials: include`를 사용한다.
- 만료된 Authorization 헤더는 로그아웃을 막지 않으며 Bearer·본문의 토큰이 Refresh 쿠키를 대신하지 않는다.
- 성공은 **204 No Content**, 빈 본문, `Cache-Control: no-store`, `Pragma: no-cache`다. `bareum_refresh`와 `XSRF-TOKEN`을 발급과 같은 Path·HttpOnly·Secure·SameSite·호스트 범위로 삭제한다.
- 프론트는 204를 JSON으로 파싱하지 않고 토큰·사용자·문서·분석 상태를 비우며 상태 조회를 중지하고 로그인 화면으로 이동한다. 이 동작을 서버가 대신 수행하거나 분석 작업 자체를 취소하지 않는다.
- 프론트는 갱신·로그아웃을 직렬화하고 로그아웃 시작 후 도착한 갱신 응답으로 인증 상태를 복구하지 않는다. 다음 쿠키 인증 전에는 CSRF를 다시 조회한다.

| 응답 | 조건 |
|---|---|
| 204 | 정상·반복·누락·알 수 없거나 만료된 쿠키. 유효한 CSRF는 필요 |
| 401 AUTH-0021 | 중복 Refresh 쿠키로 폐기 대상이 모호함 |
| 403 AUTH-0018 | CSRF 쿠키·헤더 누락/불일치·중복. 폐기·쿠키 삭제 없음 |
| CORS 403 | 허용하지 않은 Origin. 브라우저에서 응답 본문을 읽지 못할 수 있음 |
| 503 AUTH-0019 | 인증 저장소·커밋 장애. 폐기 롤백, 성공·쿠키 삭제 응답 없음 |

## 폐기와 동시성

- JWT 서명·용도·회원·family를 검증한 뒤 **회원 → 해당 family의 세션** 순서로 잠근다. 서명 검증된 회원 ID를 사용하므로 별도 해시 기반 회원 조회를 반복하지 않는다.
- 현재 Refresh 해시 또는 같은 세션·family에서 소비된 Refresh 해시인지 잠금 안에서 확인한다. 서명만 유효하고 DB에 등록되지 않은 토큰으로는 세션을 폐기하지 않는다.
- 세션과 같은 family의 등록 Access를 모두 폐기한다. 다른 회원과 재로그인으로 생성된 새 family에는 영향을 주지 않는다.
- 갱신 전 Refresh로도 같은 family를 종료한다. 갱신이 먼저 완료되면 새로 발급된 Access까지 폐기하고, 로그아웃이 먼저 완료되면 갱신을 거부한다.
- 반복 종료로 세션·Access의 최초 폐기 시각을 변경하지 않는다. 저장 실패 시 전체 폐기를 롤백한다.
- 만료된 Refresh는 명시적 종료에서만 허용한다. 일반 인증·갱신은 만료를 계속 거부하며, 로그아웃도 서명·용도·필수 claim 검증은 생략하지 않는다.
- 계정 상태·가입 방식 때문에 종료를 차단하지 않는다. 정지·탈퇴 상태와 Google 회원도 같은 폐기 경로를 사용한다.
- 신규 환경변수·의존성·마이그레이션은 없다. #37의 로그인·CORS·쿠키 설정과 #38의 소비 토큰 저장 구조를 재사용한다.

## 선택지·영향·재검토 조건

| 쟁점 | 구현안·영향 | 재검토 조건 |
|---|---|---|
| 인증 전달 | Refresh 쿠키 + 마스킹 CSRF 헤더. Access가 만료돼도 종료 가능 | 프론트 계약 검토 시 |
| 성공·반복 처리 | 없는·만료된 토큰도 204와 쿠키 삭제. 로그인 존재 여부를 응답으로 구분하지 않음 | 프론트 오류·재시도 처리 검토 시 |
| 폐기 범위 | 현재 쿠키의 family만 종료. 모든 기기 로그아웃은 추가하지 않음 | 다중 기기 정책 변경 시 |
| 쿠키·동시 응답 | Refresh·CSRF 삭제, 갱신 직렬화. 늦은 갱신 응답이 쿠키를 기록해도 폐기된 토큰으로 인증할 수 없음 | 실제 브라우저·다중 탭 통합 검증 시 |

## 검증과 적용 조건

- Java 25·PostgreSQL 17에서 `check bootJar`: 전체 496개 통과, 실패·오류·건너뜀 0개. 종료·쿠키·CSRF·재사용·재로그인 경쟁·만료 검증 분리·DB 저장/커밋 실패 롤백을 확인했다. Spotless·Flyway 중복 검사·JAR 빌드와 저장소 정적 검사도 통과했다.
