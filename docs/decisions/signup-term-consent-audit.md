# 가입 약관 버전 검증 제외 점검

## 개발 기준

- AUTH-001·AUTH-011은 age·service·privacy 필수 동의를 확인한다. 미동의는 TERM-0003/400으로 가입 실패 처리한다.
- marketing의 동의·거부 응답을 모두 저장한다. 회원·동의 이력·가입 증명 소비는 같은 트랜잭션으로 처리한다.
- 약관 버전 비교·유효성·빈 문자열 검사, 별도 버전 설정과 관련 503 응답은 현재 개발에서 제외한다.
- 동의 이력의 약관 ID·버전·시각 기록은 유지한다. 버전은 연결된 DB 약관의 기록이며 가입 요청의 검증 조건이 아니다.
- DB 약관 누락·중복·필수 여부 오류는 동의를 저장할 수 없는 데이터 오류로 TERM-0004/500 처리한다. Google 가입 저장소 장애 AUTH-0030/503 및 이메일 인증 설정 오류는 별도 동작이다.

## 코드와 설정 확인

현재 Auth·Term 작업 브랜치 11개에서 공통 검증기, 이메일·Google 가입 경로, DTO, OpenAPI, 테스트, application 설정과 배포 생성기를 대조한다.

- SignupTermProperties·SignupTermConfig와 네 SIGNUP_TERMS 버전 환경변수의 런타임 의존성 제거.
- 공통 SignupTermConsentValidator에 버전 조회·비교·형식 검사 없음.
- 필수 동의 검증·선택 응답 저장·트랜잭션 롤백 유지.
- TERM-001의 버전 조회 응답과 DB 이력 필드는 유지하며 검증 코드로 오인하지 않음.

## PR과 이력 구분

- 현재 열린 #57은 인증번호 확인이며 약관 검증 코드가 없다. 이메일 확인 설정 관련 503은 약관 버전 정책과 무관하다.
- 닫힌 #33·#37·#38·#39·#40·#41·#45·#46은 재개하거나 병합하지 않는다. 현재 작업 브랜치의 수정 코드와 검증 근거를 PR 본문에 연결한다.
- 닫힌 PR의 과거 diff·리뷰·커밋과 codex/22-auth-term-review-baseline 기준 스냅샷은 과거 기록이다. 이력을 강제 변경하지 않으며 현재 배포·후속 개발 소스로 사용하지 않는다.
- develop·main과 이미 병합한 PR의 이력은 이 변경으로 수정하지 않는다. 후속 PR은 순차 병합 기준에서 이미 반영된 공통 변경을 제외하고 비교한다.
