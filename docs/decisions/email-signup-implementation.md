# 이메일 회원가입·약관 동의 저장 적용 기준

- 대상: AUTH-001, GitHub #23
- 상태: 구현안·팀 검토 필요. 공식 약관·실제 배포 준비와 구분한다.
- 선행 기능: #18 발송, #57 인증번호 확인, #27 재발송

## 기준과 범위

- [최근 공유 화면 기획](https://app.notion.com/p/8db11880adea821da91f01c46e4d3804)과 [기술·정책](https://app.notion.com/p/3e311880adea8077a667c9a8eae3d107)의 최소 12자·영문·숫자·허용 특수문자 포함·공백 금지를 유지한다. 오래된 AUTH-001의 8~12자 표기보다 최근 공유 기준을 따른다.
- [약관 동의 저장 기준](signup-term-consent.md)에 따라 네 boolean 동의를 DB 약관에 연결한다. 별도 버전 설정·비교와 원문 확정 대기 503은 사용하지 않는다.
- 기존 발송·확인·재발송 구현은 재사용하며, 이 변경에는 해당 API나 Outbox·배포 스크립트를 다시 추가하지 않는다.
- #18·#57·#32와 Spotless #59가 병합된 develop을 기준으로 한다. 기존 발송·확인·재발송 API의 계약과 SSM 11개 주입 설정은 유지한다.

## 처리 흐름

1. `POST /api/v1/auth/signup`의 이메일·이름·비밀번호·완료 증명·네 boolean 약관 동의를 검증한다.
2. 동일 이메일 잠금 아래 최신 SIGNUP 요청의 발송 완료·인증 완료·증명 해시·만료·미사용 상태를 확인한다.
3. 이메일·Google 가입 방식과 관계없이 대소문자를 무시한 중복 가입을 차단한다. #18의 `member_email_key` 제약 이름과 탈퇴 처리 기준을 사용한다.
4. age·service·privacy 필수 동의와 marketing 선택 동의를 확인하고 DB 약관에 연결한다. 버전은 연결된 DB 행으로 기록하며 별도 설정과 비교하지 않는다. 약관 데이터 누락·중복·잘못된 필수 여부는 TERM-0004/500의 서버 데이터 오류로 처리한다.
5. Argon2id로 비밀번호를 해시한다. 해시 처리 후 증명 만료를 다시 확인하고 회원·네 동의 이력·증명 소비를 한 트랜잭션으로 저장한다.
6. 성공은 201과 회원 ID를 반환하며 자동 로그인하지 않는다. 비밀번호·인증 증명 원문은 응답·로그에 기록하지 않는다.

동의나 저장이 실패하면 회원·동의·증명 소비를 함께 롤백한다. 가입을 완료한 증명은 다시 사용할 수 없다.

## 중복 가입 경합과 DB 오류

사전 중복 검사 이후 다른 요청이 같은 이메일로 회원을 생성할 수 있으므로 최종 방어는 `member_email_key` 고유 인덱스가 담당한다. Hibernate가 지역화된 오류에서 제약 이름을 추출하지 못하는 경우에도 PostgreSQL의 SQLState `23505`, 테이블 `member`, 제약 `member_email_key`를 함께 확인해 `AUTH-0001/409`로 변환한다. 다른 고유 제약이나 DB 오류를 이메일 중복으로 분류하지 않는다. 판별에는 오류 메시지 문자열을 사용하지 않는다.

PostgreSQL JDBC의 [구조화된 오류 정보](https://jdbc.postgresql.org/documentation/publicapi/org/postgresql/util/ServerErrorMessage.html)를 참조하므로 기존 드라이버의 Gradle 범위를 `runtimeOnly`에서 `implementation`으로 변경한다. 드라이버 버전과 DB 스키마는 변경하지 않는다.

## 설정과 후속 범위

약관 버전 환경변수는 사용하지 않는다. 원문은 프론트가 표시하며 개발 중 임시 원문을 사용할 수 있다. 동의 이력 연결을 위한 네 약관의 DB 데이터는 원문과 별도로 준비한다. 실제 사용자 가입 전에는 표시 원문과 DB 버전의 대응을 확인한다.

#54의 실패 제한·완료 증명 복구, 로그인·Google 인증·비밀번호 재설정과 전체 배포 정비는 별도 변경이다. #32의 확인 정책 두 항목과 SSM 11개 주입을 그대로 유지하며 이번 회원가입 변경은 환경변수를 추가하지 않는다. 후속 배포 정비에서도 제거한 약관 버전 환경변수를 다시 필수로 요구하지 않도록 최신 기준과 대조한다.

## 검증 결과

- `./gradlew check bootJar --no-daemon`: #32 최신 리뷰 수정과 Spotless 반영 후 Java 25·PostgreSQL 17에서 전체 338개 테스트 통과, 실패·오류·건너뜀 0개, JAR 빌드 성공.
- `spotlessApply`·`spotlessCheck` 및 하네스 정적 검사 통과. PostgreSQL 18·ARM64 이미지 검증은 선행 PR 병합 후 기존 #33 재오픈 시 CI에서 확인한다.
- 회원가입 Controller 27개·OpenAPI/HTTP 1개·서비스 통합 37개, 비밀번호 정책 28개·해시 4개 통과. 약관 버전 설정 없이 DB 버전과 동의 응답을 저장하는 회귀 검증을 포함한다.
- PostgreSQL에서 회원·동의·증명 소비의 원자성, 동시 가입, 저장 실패 후 재시도, 해시 처리 중 증명 만료, 재발송→이전 번호 거부→새 번호 확인→가입을 검증했다. A→B→A로 과거 번호가 다시 생성된 뒤에도 이전 발송 타이머는 무효이며, 최신 인증 증명으로 한 번만 가입되고 네 동의가 저장되는지 확인했다. 사전 중복 확인 직후 Google 가입 계정이 생성되는 실제 DB 경합과 다른 고유 제약 오류의 구분도 검증했다.
- 공식 약관 데이터·실제 메일 제공자·배포 서버·프론트 브라우저 검증은 포함하지 않았다.
