## 범위

이메일 로그인 가능한 활성 계정의 비밀번호를 이메일 인증 완료 증명으로 변경한다. Google 전용 계정에 비밀번호를 추가하거나 자동 로그인하는 기능은 포함하지 않는다. 최신 MVP 표에서는 제외된 기능이므로 3순위 개발 초안으로 관리하며, Sprint 1·배포 포함은 별도 팀 확인이 필요하다.

## 공개 API 계약

`PATCH /api/v1/auth/password/reset`

```json
{
  "email": "user@example.com",
  "verificationToken": "<PASSWORD_RESET 인증 완료 증명>",
  "password": "<회원가입과 같은 조건의 새 비밀번호>"
}
```

- 인증 증명은 AUTH-006에서 PASSWORD_RESET 목적의 인증번호를 확인한 응답을 사용한다. Access Token이나 Refresh 쿠키는 이를 대체하지 못한다. 원문 증명은 메모리에서 관리하며 URL·로그에 남기지 않는다.
- 성공은 204와 빈 본문, `Cache-Control: no-store`이다. 쿠키를 발급·삭제하거나 자동 로그인하지 않는다. 프론트는 재설정 완료 후 로그인 화면으로 이동한다.
- 400: 입력 검증, 비밀번호 정책 위반(AUTH-0012), 인증 증명 무효(AUTH-0007)·만료(AUTH-0013), 변경 불가 계정(AUTH-0003).
- 404: 유효한 증명에 대응하는 변경 대상 계정 없음(AUTH-0002).
- 500: 저장·커밋 실패. 비밀번호·증명 사용·기존 세션 폐기는 모두 롤백한다.
- 400 응답 문서는 공통 `BadRequestProblemDetail`의 anyOf로 일반 오류와 필드 오류를 표현한다. 요청 비밀번호·증명은 writeOnly이며 DTO의 toString에도 원문을 포함하지 않는다.

## 구현 선택과 영향

- 최신 PASSWORD_RESET 요청만 확인한다. 이메일·목적·토큰 해시·발송·인증 완료·증명 만료·미사용 상태를 검증한다. 대기 중이거나 SIGNUP 목적의 증명은 사용할 수 없다.
- 이메일 비교·잠금·DB 제약은 기존 upper(email) 기준을 유지한다. 회원의 등록 주소는 변경하지 않으며 재설정 메일은 기존 발송 서비스가 등록 주소로 보낸다.
- 최초·재발송 접수, worker의 발송 직전 검사, 최종 재설정 모두 활성 LOCAL 계정이며 비밀번호 해시가 있는 경우만 허용한다. 접수 후 제한된 계정의 대기 작업은 메일 전송 없이 CANCELLED로 종료하고 암호문을 삭제한다. 탈퇴·정지·Google 전용 계정은 제외하고, 탈퇴 후 이메일을 재사용한 새 계정에는 생성 이전의 인증 요청을 허용하지 않는다.
- 이메일 advisory lock 후 회원 행을 잠그고 세션을 갱신한다. 기존 로그인·갱신과 member → session 순서를 유지한다. 재설정 전에 검증한 이전 비밀번호로는 변경 이후 새 세션을 발급할 수 없다.
- 회원가입의 최소 12자·영문·숫자·허용 특수문자·공백 금지 정책과 Argon2id 해시를 재사용한다. 저장 직전에도 증명 만료를 확인한다.

## 설정과 인증 흐름

- 최초·재발송은 기존 Outbox의 202 접수·상태 조회를 사용한다. PENDING에서는 인증 타이머를 시작하지 않고 SENT의 expiresIn으로 시작한다. 번호 확인 이후에는 응답 증명과 별도 expiresIn을 사용한다.
- `EMAIL_VERIFICATION_PASSWORD_RESET_CODE_TTL_SECONDS`, `EMAIL_VERIFICATION_PASSWORD_RESET_VERIFICATION_TTL_SECONDS`, `EMAIL_VERIFICATION_MAX_VERIFICATION_ATTEMPTS`를 application.yml의 기존 인증 속성에 연결했다. 값을 자동으로 확정하지 않으며 필수 값이 없으면 발송·확인을 차단한다.
- 기존 SMTP·해시 비밀키·Outbox 암호화 키·발송 횟수 설정도 필요하다. 비밀값은 공유 문서·저장소에 기록하지 않는다.
- 실제 프론트 브라우저 연동과 운영 메일 서비스·발신 계정 결정은 남아 있다.

## 기존 실제 메일 수신·재설정 연결 검증 — JWT·Argon2id 변경 전

- Gmail SMTP로 PASSWORD_RESET 메일을 실제 수신하고, 등록 수신 주소·인증번호 HMAC 해시·발송 시각·만료 시각·발송 이력의 일치를 확인했다.
- 202 접수·PENDING의 expiresIn=0, SMTP 수락 후 SENT 전환·남은 유효시간, 완료 후 Outbox 암호문 삭제와 해당 작업의 발송 이력 1건을 확인했다.
- 수신한 번호로 인증 확인 API를 호출해 완료 증명을 발급받았다. DB의 증명 SHA-256 해시·유효기간을 확인하고 PATCH 재설정의 204·빈 본문·no-store를 검증했다.
- 비밀번호 해시 변경·증명 사용·기존 세션 폐기의 저장 시각이 일치했다. 이전 비밀번호·Access Token·Refresh Token과 소비된 인증 증명은 거부됐으며, 새 비밀번호 로그인과 같은 회원의 /me 조회는 성공했다.
- 번호 300초·완료 증명 600초·실패 제한 3회는 이번 검증의 테스트 설정이다. 운영 기본값이나 팀 확정 정책으로 사용하지 않는다.
- 실제 브라우저의 쿠키·CSRF·다중 탭 연동은 미검증이다. 운영 메일 서비스·발신 계정과 재설정 배포 범위·세션 폐기 정책은 별도 결정이 필요하다.
