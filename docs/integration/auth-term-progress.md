## 이번 재검증에서 반영한 내용

- 인증번호 해시 검증은 DB에 저장한 이메일을 사용한다. 요청 이메일의 Unicode 대소문자 변환 차이로 정답이 거부되지 않도록 발송→Outbox 완료→확인→증명 저장 회귀 검증을 후속 준비 코드에도 반영했다.
- 인증 확인 서비스는 DB 기본 격리 수준을 사용한다. 불일치 예외의 실패 횟수 커밋과 동일 이메일 잠금은 유지한다.
- 가입 증명 TTL=0은 정상 실패 허용 횟수 3과 함께 독립 검증한다. #54의 5회·900초·재설정 증명 600초 기본값은 유지한다.
- 후속 정책 문서의 Origin을 운영·develop 두 주소로 맞추고, Client ID 발급 상태와 기존 닫힌 PR 재사용 방침을 갱신했다.

## 배포·프론트 연동

- 프론트 운영은 `https://bareum.site`, develop은 `https://bareum-web-git-develop-numkites-projects.vercel.app`이다. [발급된 Google Client ID와 환경 등록 값](frontend-origins.md)을 따른다.
- 두 Google 승인 원본은 클라이언트 생성 화면에 입력했다. CORS와 `GOOGLE_CLIENT_IDS`의 실제 AWS 등록·인증 이미지 배포는 아직 미완료다.
- 메일은 202 접수 후 1초 간격 상태 조회, SENT의 남은 초로 타이머 시작, FAILED 시 실패 안내 기준이다. 별도 지연 안내·1분 초과 실패는 추가하지 않는다. 프론트 연결과 실제 검증은 남아 있다.
- 개발 약관은 네 boolean 동의와 개발 DB 데이터를 사용한다. 별도 버전 비교·관련 503은 제외하며 실제 사용자 적용 전 공식 원문·DB 기록의 대응을 확인한다.
- 다음 리뷰 대상은 #57 병합 뒤 기존 #32다. 기존 PR을 새 PR로 대체하지 않으며, 병합 완료 코드와 아직 미병합인 후속 공통 변경이 다음 diff에 중복되지 않도록 확인한다.
