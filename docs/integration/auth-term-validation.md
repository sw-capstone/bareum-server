# Auth·Term 실제 연동 검증 시나리오

- 관련 업무: #22, #56 / 정책: #54
- 상태: 검증 계획. 아래 표는 실제 배포·브라우저 검증 완료 기록이 아니다.
- 요청·응답 기준: [Auth·Term 연동 안내](auth-term.md)
- 설정 기준: [Auth·Term 배포 설정 준비](../guide/auth-term-deployment.md)

## 실행 전 준비

1. 각 기능의 병합 커밋·배포 이미지와 공개 OpenAPI를 확인한다. #18 메일 발송 설정만으로 전체 인증이 준비됐다고 판단하지 않는다.
2. 메일 기본 설정 9개·SMTP 템플릿이 유지되는지 확인한다. 전체 인증을 활성화할 때는 JWT·허용 Origin·약관 버전·확인 정책을 추가한다.
3. 실패 5회·900초 제한·증명 분실 복구는 #54 코드와 설정이 함께 반영된 환경에서 검증한다. 확인 실패 제한 값만 추가해 복구 검증을 대체하지 않는다.
4. 개발 가입 검증에는 임시 원문과 네 약관의 개발용 DB 데이터를 사용할 수 있다. 실제 사용자 적용 전 표시 원문·DB 버전 대응을 확인한다. 별도 약관 버전 환경변수는 필요하지 않다. 테스트 Client ID로 운영 준비 완료를 표시하지 않는다.
5. 실제 프론트 Origin, Google Client ID·Console 등록, 메일 수신 가능한 검증 계정을 준비한다. 개인정보·토큰·키 원문을 검증 기록에 남기지 않는다.

## 정상·실패 시나리오

| 영역 | 수행 | 기대 결과 |
| --- | --- | --- |
| 최초 메일 | 발송 접수 후 상태 조회 | 202·requestId를 받고 PENDING 동안 타이머를 시작하지 않음. SENT부터 남은 초 사용 |
| 메일 실패 | 지연·재시도·최종 실패 상태 확인 | 작업 상태별 안내. FAILED·CANCELLED는 0초. 접수 성공을 수신 완료로 표시하지 않음 |
| 재발송 | 새 번호 접수 후 이전 ID·번호 확인 | 새 requestId 사용, 이전 응답의 화면 덮어쓰기 방지, 이전 번호 거부, 새 번호는 발송 완료 후 확인 가능 |
| 발송 제한 | 대소문자·가입/재설정 목적을 바꿔 반복 요청 | 최소 간격·최근 1시간/24시간 합산 제한 유지, 거절된 요청으로 기존 증명을 소비하지 않음 |
| 인증 확인 | 정답·오답·만료·재확인 | 완료 증명 발급, 오답 횟수 저장, 만료 거부, 단순 재확인으로 증명 원문 재발급 불가 |
| 실패 복구 | 5회 실패 직후와 900초 경계에 새 번호 요청 | 제한 중 확인·최초/재발송 우회 불가. 제한 종료 후 새 번호 접수 커밋으로 재시작, 이전 번호는 복원하지 않음 |
| 증명 분실 | 완료 증명을 잃은 뒤 재발송·재인증 | 새 접수 커밋 시 이전 미사용 증명 무효화. 접수 실패면 기존 상태 보존. 이메일만으로 증명을 재조회하지 않음 |
| 이메일 가입 | 인증 후 필수 동의·선택 동의 조합으로 가입 | 회원·네 약관 이력·증명 소비가 함께 저장됨. 마케팅 미동의 가능. 자동 로그인하지 않음 |
| 가입 차단 | 증명 만료·재사용·잘못된 목적·중복 이메일·필수 약관 미동의 | 오류와 안내가 일치하며 회원이나 동의 이력만 부분 저장되지 않음 |
| 로그인 | 이메일 로그인 후 사용자 정보 조회 | Access·Refresh/CSRF 계약에 따라 로그인·사용자 조회 성공, 비밀번호·토큰 원문이 로그에 없음 |
| 갱신 | Access 만료 후 갱신, 동시 갱신·응답 유실 | 계약에 따른 갱신·오류 처리. 프론트의 중복 요청 방지·응답 유실 처리 기준을 확인 |
| 로그아웃 | 로그아웃 뒤 이전 인증정보 재사용 | 쿠키 삭제·세션 폐기 확인, 이전 인증정보로 보호 API 접근 거부 |
| 브라우저 | 실제 HTTPS Origin에서 쿠키·CORS·CSRF 확인 | credentials 전송, 허용 Origin만 허용, CSRF 누락·불일치 거부, 다중 탭·재접속 흐름 확인 |
| Google | 기존 회원·Gmail/검증된 Workspace 신규 가입 | 실제 Client ID 검증, 기존 회원 로그인 또는 신규 약관 동의·가입 분기. LOCAL 이메일 중복 가입 차단 |
| 지원 제한 | 제3자 이메일 Google 신규 가입 | AUTH-0028/403과 지원 범위 안내. 아직 없는 추가 인증 화면으로 이동시키지 않음 |
| 비밀번호 찾기 | 배포 포함이 확정된 경우에만 인증·재설정 | 번호와 완료 증명 만료 구분, 새 비밀번호 적용·기존 세션 폐기, 별도 로그인. MVP 제외 기준 유지 |

조회 간격·총 대기 한도·응답 유실 후 복구 화면은 프론트와 확인할 항목이며 이 문서에서 새 수치나 자동 재요청 정책을 확정하지 않는다. 타사 쿠키 차단 환경에서 갱신이 불가능하면 합의된 서브도메인·프록시 전환안을 재검토한다.

## 결과 기록

실행별로 배포 커밋·이미지, 브라우저와 프론트 Origin, 시나리오, 기대/실제 결과, 통과·실패·미수행, 후속 이슈를 기록한다. 미수행·환경 미준비를 통과로 집계하지 않는다. 서버 테스트·모의 SMTP 결과와 실제 AWS·메일 수신·브라우저 검증은 분리한다.
